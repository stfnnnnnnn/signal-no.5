# Frontend M5–M9 Implementation Plan (concise)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (approved method: Native). Steps use `- [ ]`.
> Concise by the owner's request: exact files, interfaces, tests and acceptance per task; pure logic is test-first,
> components get react-dom/server render tests, visual behaviour is verified in the real Electron app.

**Goal:** A complete playable journey on top of the M1–M4 slice: title → onboarding (custom or random) → customization → house →
storm progression with SceneDirective visuals → HUD/inventory/shop → evacuation or shelter-in-place → debrief, badges,
achievements, preparedness guide → save/continue/replay.

**Architecture:** Unchanged. `EngineStore` stays the only game state; a new `appStore` holds which screen is shown.
React renders screens and overlays; Phaser renders the world and directive visuals; all rules, prices, eligibility,
badges, achievements and scores come from `src/core` / `window.signal`.

**Spec:** `docs/frontend/FRONTEND_IMPLEMENTATION_BLUEPRINT.md` §3 (screens), §4.3–4.5, §5.9–5.13, §7, §8, §10 (B1–B11, A4–A7);
`docs/implementation/FRONTEND_BACKEND_CONTRACTS.md` (SceneDirective); `docs/frontend/FRONTEND_BACKEND_INTEGRATION.md`.

## Global Constraints
- Frontend-owned files only (`src/renderer/**`, `tests/renderer*/**`); backend changes only for confirmed blockers, reported.
- No new dependencies. No neighbour NPC. "Wellbeing", never "health". Exposure and scenarios labelled fictional.
- Question text/choices only from `ONBOARDING_QUESTIONS`; validation errors only from `createGame` `error.issues`.
- Directive values only from `SceneDirective` enums; apply a directive only when it differs (JSON compare).
- One toast per `badgeEarned` / `newlyUnlocked` id; `recordRun` once per runId.
- Saves only through `window.signal.save` with engine `GameState`; settings in localStorage wrapped in try/catch.
- Every suite run stays green (417 + new), typecheck clean, production build passes, prod-CSP boot shows `missing=[]`.

## Review Focus
1. Starting a second game after a first one (replay/new household): no stale engine state, toasts, AI cache, Phaser scene or pauses.
2. Continue with a corrupt or missing save: "can't be loaded" + delete option, never a crash.
3. Directive refresh every tick: visuals/audio keys must not restart when the directive is unchanged.
4. Household in transit at landfall: STREET scene, no home flood/hazards shown.
5. Debrief reached twice (re-render, StrictMode): `recordRun`/`markPlanViewed`/badge persistence happen once.

## Assets
Reuse: 4 character sheets (player + up to 3 household NPCs; `paletteId` variants rendered as 4 tints since the art has one
outfit per character), 21 item sprites (inventory icons), 22 badge/achievement icons.
Placeholders (generated in Boot, clearly simple): rain/debris particles, lightning, flood water, lighting overlays, props
(boarded window, sandbags, raised belongings, flashlight, go-bag states, 12 decor variants as small coloured shapes),
NPC emotion bubbles, pet sprite, shop/street/evacuation-centre rooms. No audio files exist: `AudioDirector` tracks the
ambient key and one-shots (logged, mute-able) and plays nothing until audio is supplied.

## M5 — Title, onboarding, customization (B1–B3)

**Task 5.1 App shell + appStore**
- Create `state/appStore.ts`: `type Screen = 'title'|'mode'|'custom'|'random'|'customize'|'game'|'debrief'|'achievements'|'settings'`;
  `go(screen)`, `startRun(input|profile, seed)` (resets EngineStore, UiStore, AI cache; bumps `runKey` so `<PhaserGame key>` remounts), `subscribe`.
- `EngineStore`: add `startProfile(profile, seed)` (`startRun`) and `load(raw)` (`loadGame`), both returning `{ok}|{ok:false,error}`.
- `UiStore.reset()`; `services/ai.ts` `clearScenarioCache` used on new runs.
- Rewrite `app/App.tsx` as a screen router; remove `sliceHousehold` from runtime (kept for tests).
- Tests: `tests/renderer/appStore.test.ts` — a second `startRun` leaves no event listeners, toasts, menu pause or old state (Review Focus 1).

**Task 5.2 Title screen** `ui/screens/Title.tsx`: New Game, Continue (only if `save.list()` has `auto`), Achievements, Settings,
Exit (`window.close()`); AI status line. Render test (SSR): Continue hidden without a save.

**Task 5.3 Onboarding logic (pure, test-first)** `ui/onboarding/onboardingModel.ts`:
- `toggleChoice(selected, value, question)` honours `exclusive`; `visible(question, draft)` for Q2b (`q2SizeRange in [3-4,5-6,7+]`) and R3 (`r1SizeRange != 1`);
  `ageTotal(draft)`; `toCustomInput(draft, customization)`, `toRandomInput(draft)`; `issuesByField(error.issues)`.
- Tests: exclusive Neither/Not sure; Q2b only for ranges; R3 hidden for size 1; R4 skippable (omitted → backend default);
  a valid draft builds a game via `createGame`; an invalid age total maps the backend issue to `q3AgeCounts`.

**Task 5.4 Onboarding screens** `ui/onboarding/{ModeSelect,CustomForm,RandomForm,QuestionView}.tsx`: one question per step,
Back/Next, live age total, inline backend errors; random path shows a generated preview (`getProfile()` roster, fictional exposure)
with **Re-roll** (new seed). SSR test: no apartment/condominium text anywhere; Q0 shows the exact two labels and details.

**Task 5.5 Customization + review** `ui/onboarding/Customize.tsx`: theme (modern/traditional), which member you play
(`playerMemberIndex`), appearance (auto / custom colour / randomize), minimum-budget challenge; review card (roster, budget,
fictional exposure). Start → `appStore.startRun(input with customization, seed)` → `game`.
House/Boot: player and visible NPC sprites tinted by `paletteId`/`clothingColor`; theme swaps tile colours only (layout test already guarantees identical collision).

**M5 acceptance:** both paths start the real house with the configured player; replay/new game shows no stale state; commit `Frontend M5: …`.

## M6 — SceneDirective rendering, NPCs, scenes (A4–A6)

**Task 6.1 Directive logic (pure, test-first)** `game/directive.ts`: `directiveChanged(prev, next)`, `addedEffects(prev,next)`
(one-shots like `LIGHTNING_FLASH` only when newly added), `phaserSceneFor(sceneId, location)`:
HOUSE/HOME_IMPACT/AFTERMATH→`House`, SHOP→`Shop`, STREET→`Street`, EVACUATION→`Evacuation`. Tests incl. Review Focus 3–4.

**Task 6.2 Store + AI suggestion** `EngineStore.directive()`: recomputed after results containing `sceneChanged/phaseChanged/milestone/
purchaseCompleted/actionCompleted`; `services/ai.suggestSceneFor(req, runId)` once per `basisKey`, merged with `mergeSceneSuggestion`
(stale-safe by the backend). Test: same basisKey → one bridge call; null suggestion → deterministic directive.

**Task 6.3 Renderer** `game/systems/SceneDirectiveRenderer.ts` (used by every world scene): weather sky tint + rain particles
(rain level → rate), wind debris/sway, lighting overlay per `LightingPreset` (outage presets never show electric light),
flood overlay alpha per `FloodOverlay` with ripples (outdoor tiles + floor tint; player never drawn "in" water),
effects set, props at new `PROP_ANCHORS` in `layout.ts` (tested: every PropAnchor has a reachable-room anchor), NPC cues,
mood → HUD accent, transition → camera fade / rain wipe / flash. Applies only on `directiveChanged`.

**Task 6.4 NPCs + pets** `game/systems/NpcSystem.ts`: `characters.filter(visibleNpc)` (≤3) at `NPC_SPAWNS`, tinted sprites,
emotion bubble from cues, animation mapping (idle/walk frames + bob/pace tween for `pacing`); `interact(npcId)` through the existing
proximity system; dependents drawn near an adult, never interactable; pets at `PET_AREA`. No neighbour.

**Task 6.5 Other scenes** `game/scenes/{Shop,Street,Evacuation}.ts`: small generated rooms with the player; Shop opens the
React shop (M7); Street/Evacuation show a **Continue** control (`skipToNextMilestone()`) when no event is open, as do impact
and aftermath (blueprint §7). Scene switch on `sceneChanged`.

**M6 acceptance (real app, accelerated with speed/Continue):** weather, lighting, flood and props visibly follow the run;
outage lighting; a departure shows STREET and never HOME_IMPACT; commit `Frontend M6: …`.

## M7 — HUD, inventory, shop, wellbeing (B4, A7, B6, B7)

**Task 7.1 HUD** `ui/hud/*`: clock, speed buttons 1–32× (`setSpeed`), paused indicator (`pauseReasons`), phase, landfall
countdown only when `landfallRevealed`, advisory / evacuation-advisory banners, critical-speed banner on `speedChanged{critical}`,
cash, phone battery, go-bag status, AI status. Re-render throttled to ~4 Hz (`useThrottledEngineState`). Pure `hudModel(state)` tested.

**Task 7.2 Wellbeing** meter `current/max` with colour bands; toast with the rule's reason when `wellbeingEvents` grows (once per entry; tested).

**Task 7.3 Objectives panel** from `engine.evaluate().categories[].objectives` (met/unmet, applicable only) — read-only, no rule logic.

**Task 7.4 Inventory** (`I` key / HUD button, pauses `menu`): house vs go-bag lists with `ITEM_LABELS` + item icons; missing go-bag
categories (`missingGoBagItems`). Render test: matches state after `FILL_CONTAINERS`.

**Task 7.5 Shop** `ui/shop/ShopPanel.tsx` (SHOP scene, `pause('shop')`): `getShopCatalog()` price/stock/affordable, quantity,
`purchase()`, errors verbatim, Return home (`executeAction('RETURN_HOME')`). Test: purchase updates cash/inventory via store; `INSUFFICIENT_FUNDS` shown.

**M7 acceptance:** a player can read time, phase, warnings, resources, wellbeing and objectives without devtools; commit.

## M9 — Debrief, preparedness guide, save/continue/replay, settings (B8, B10, B11)

**Task 9.1 Run end** on `runCompleted`: `evaluate()`, `persistBadges`, `recordRunOnce`, then `debrief` screen.
**Task 9.2 Debrief** `ui/debrief/*`: score + ending card **separate** from the Handa badge card (`handa` breakdown: wellbeing ≥ 85
raw, critical objectives, evacuation/assistance); categories; strengths, gaps, lessons; all 12 badges with status
(not applicable neutral); timeline; AI narration (`narrateDebrief`, "AI-personalized" only when `source==='ai'`, fallback otherwise).
**Task 9.3 Preparedness guide** (`checklistItems` + `learningPoints`, printable view) → `achievements.markPlanViewed(runId)` once.
**Task 9.4 Save/continue** autosave slot `auto` on `phaseChanged` + manual save in a pause menu (Esc); Continue: `save.read` →
`EngineStore.load` → `game`; null/`INVALID_SAVE` → message + delete. Tests with a fake bridge (Review Focus 2).
**Task 9.5 Replay** same household new seed (`startProfile(profile, seed)`), new household (→ mode), title.
**Task 9.6 Settings** volume, mute, text size (CSS scale) in localStorage with try/catch.
**M9 acceptance:** finish a run, review debrief/guide, restart the app, achievements persist, continue a save, replay; commit.
